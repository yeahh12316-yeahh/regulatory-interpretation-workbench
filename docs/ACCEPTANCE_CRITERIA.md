# 外规解读 Agent 网站验收标准

## 验收方式

所有验收必须在浏览器中完成，并保留 Task ID、输入文件哈希、Prompt 版本、QC 结果和输出版本。不得以静态截图或手工脚本结果替代网站验收。

## 基础流程验收

- 用户可以选择金融机构类型、业务范围、地域和解读时点。
- 用户可以上传 PDF，并看到文件校验、解析和任务状态。
- 用户可以查看 S1、S2、S3、S4、S5、QC、Render 的实时状态。
- 任务失败时显示失败节点、原因和重跑入口。
- 浏览器刷新后任务和结果仍然存在。

## 事实准确性验收

- 法规名称、文号、机关、发布日期和施行日期可以定位到原文。
- Article 原文与源文件一致，页面位置可追溯。
- Requirement 能识别主体、动作、对象、条件、例外、时限和数字。
- “应、不得、可以、原则上、至少、不超过”等措辞不能被弱化或强化。
- 日期、金额、比例和期限的展示值必须与原文一致。
- 任何未确认事实都明确标记为待确认。

## 机构适用性验收

- 同一法规可以针对不同金融机构类型创建任务。
- 适用性结果只能取：`DIRECTLY_APPLICABLE`、`POTENTIALLY_APPLICABLE`、`NOT_APPLICABLE`、`NEEDS_REVIEW`。
- 每个适用性结果都有依据、来源位置或待确认原因。
- 机构类型不会改写监管原文。

## S5 新旧规比较验收

- 2017年版案例必须登记财政部公开路径、全文来源、文号、生效日期和下载状态。
- 2015年修订版是本案例的直接前版；仅确认其存在不等于已经具备 S5 输入。
- 新旧两份原文未取得、文件哈希未登记或版本关系未核验时，页面必须显示“待补充权威原文”，不得生成差异结论。
- 用户可以上传新规和旧规，或选择法规库中的两份已核验版本。
- 系统确认版本关系后才开始条款映射和变化比较。
- 结果能识别新增、删除、修订、范围、时间、金额、比例和阈值变化。
- 事实变化和监管含义解释分开显示。
- 缺少旧规或版本关系不明时显示待补充/待确认，不产生正式比较结论。

## 解读和证据验收

- 整体解读和逐条解读均能生成。
- 内容区分 `FACT`、`OFFICIAL`、`INTERPRETATION`。
- 每条核心解读至少关联一个 Article 或官方解释证据。
- 用户可以从解读跳转到 Requirement、Article 和原文页码。
- 没有证据的结论不能直接发布。

## QC 和审核验收

- 数字错误、条款遗漏、证据断链、范围扩大和绝对化表达能够被拦截。
- QC 未通过的内容不能进入正式报告。
- 人工可以退回、修改、通过和锁定。
- 锁定版本不会被后续自动重跑覆盖。

## 输出验收

- HTML 页面可刷新、搜索、导航和复制链接。
- Word 报告可打开，章节和条款顺序正确。
- HTML 与 Word 的原文、解读、数字、变化和证据一致。
- 报告带有版本、生成时间、审核状态和来源说明。

## 生产可用性验收

- 用户权限和机构空间隔离有效。
- 文件不通过公开永久 URL 暴露。
- 模型密钥、法规全文和敏感数据不写入普通日志。
- 数据库和源文件可备份、恢复和回滚。
- 模型超时、限流、无效 JSON 和 OCR 失败有可理解的错误提示。
